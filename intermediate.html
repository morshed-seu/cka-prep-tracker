      Containers & runtimes

      The Beginner track ends with minibox — about eighty lines of bash that runs a process on an overlay filesystem, in five namespaces, inside a cgroup, with dropped capabilities, on a bridge with NAT and DNS, supervised by systemd. That is, honestly, a container runtime. The Advanced track begins with a cluster where containerd, runc, CNI plugins and images already exist, and teaches Kubernetes on top of them. This track is the decade in between.

      Its thesis is the sequel to the beginner track's. That one argued that Kubernetes invented very little; it composes decades-old operating-system technology. This one argues that the container ecosystem added almost no mechanism — it added contracts. runc does what your minibox already did; what it adds is config.json, a schema anyone can generate. containerd's snapshotter mounts the same overlayfs you mounted by hand; what it adds is a content-addressed store and an API. CNI does nothing your networking script didn't; what it adds is "exec a binary, JSON on stdin, JSON on stdout."

      So every module runs the same arc: you already built this → here is the spec that says how everyone agrees to build it → here is the real implementation obeying that spec → now break it. Every conceptual lesson carries a “What the spec actually says” block quoting the normative text, and the beginner track's “Where this shows up in Kubernetes” block linking forward.       What you needA second throwaway Ubuntu 24.04 LTS virtual machine called buildbox (4 vCPU / 8 GB / 40 GB), built and snapshotted in I0. It is deliberately not the beginner track's sandbox — undersized for image builds, and its snapshot is that track's asset — and deliberately not the CKA lab's cp/node01/node02, because these labs stop and reconfigure containerd, which would break the cluster the Advanced track depends on. Unlike sandbox, buildbox needs working internet: pulling real images from a registry is the subject matter, not a setup step.
      Skipped the beginner track?You can start here, but two of its artefacts are assumed from I0 onwards: minibox.sh (the bash container runtime) and net-up.sh (the hand-built pod network). Both ship in labs/intermediate/seed/ so you can bootstrap them in a minute rather than build them — though the modules keep pointing back at the beginner lessons that derive them, because the whole track is an argument about what the standards added to those two scripts.
