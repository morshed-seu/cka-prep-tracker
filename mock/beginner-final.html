Beginner track final — 30 questions + 8 tasks · 90 minutes · pass ≥ 66/100

Part A is 30 recall questions worth one point each; Part B is 8 hands-on tasks worth 70 points, all run on the throwaway sandbox VM. Every recall question names the module that taught it, so a wrong answer points at a page rather than at a fact — and the instruction that matters is to re-read that module, not the answer. Do not open the solutions page until the timer rings.

90:00 The countdown survives page reloads — start it once and work.
Before you start
  1. Work on a clean sandbox VM. Take a snapshot first (B0.9) — several tasks change system state: 
    multipass stop sandbox && multipass snapshot sandbox --name pre-final && multipass start sandbox
  2. Answer files go exactly where each task says, under ~/final/ on the sandbox. A correct result in the wrong path scores zero — the same rule the CKA applies.
  3. Part A first, from memory, writing answers into ~/final/partA.txt as numbered lines. No looking anything up; a blank is worth the same as a wrong answer and takes less time.
  4. Then Part B. First pass ≤8 minutes per task; flag and skip anything sticky, second pass by points. Verify every task with its own verification line before calling it done.
  5. When the timer rings: hands off, then grade honestly against the solutions page, which carries a per-task rubric. 66 points passes. Afterwards: multipass restore sandbox.pre-final.

Part A — recall (30 × 1 pt)

  1. Name the two commands that pin a Multipass VM to Ubuntu 24.04 rather than whatever lts currently means, and say why that matters for every lab in this track. B0
  2. A file's permissions are rw-r--r-- and a user still cannot read it. Name the two things you would check, in order. B1 · B4
  3. What is the difference between fork() and exec(), and which one does a shell use when you type a command with &? B2
  4. A process shows as Z in ps. What is it holding, who is supposed to clean it up, and why does killing it do nothing? B2
  5. Which signal cannot be caught or ignored, and what exit code does a process killed by it report? B2
  6. What does a system call actually do to the CPU, and why is that transition the reason syscalls are counted rather than assumed free? B3
  7. Name the one command that shows you which syscalls a program is making, and the flag that summarises them by count. B3
  8. What is a file descriptor, and what do 0, 1 and 2 refer to by convention? B3
  9. Explain the permission check order for a file, and what "first match wins" means when the owner has fewer rights than the group. B4
  10. What does the execute bit mean on a directory, and what breaks without it? B4
  11. Root is not one flag. Name the mechanism that splits it, name one capability, and say what the bounding set is for. B4
  12. Name the four directories overlayfs needs and which one is written to. B5
  13. What is copy-up, and why does the first write to a large file in a lower layer cost so much? B5
  14. Files vanished from a directory, nothing was deleted and free space is unchanged. What is the single command you run? B5
  15. Name five namespace types and what each hides. B6
  16. Why is chroot not a security boundary, and what does pivot_root do that makes it one? B6
  17. You ran a shell in a new PID namespace and ps still lists the whole host. What did you forget? B6
  18. State the one-sentence difference between namespaces and cgroups. B7
  19. What is the difference between cpu.weight and cpu.max, and which one bites on an idle machine? B7
  20. A container exits with 137 and its own log says nothing. Name the cause and the two files that prove it. B7
  21. Recite the five-rung diagnostic ladder in order. B8
  22. A TCP connection is refused instantly versus hanging until timeout. What does each tell you? B8
  23. What does a veth pair do, and what happens when you delete one end? B9
  24. Why does NAT need conntrack, and what breaks when the conntrack table fills? B9
  25. Which netfilter chain does DNAT have to happen in, and why can it not be INPUT? B9
  26. ping resolves a name and dig does not agree with it. Which file explains the disagreement? B10
  27. What does ndots:5 do to the lookup of google.com, and what single character makes it stop? B10
  28. What is the difference between systemctl start and systemctl enable, and which single command does both? B11
  29. (code=exited, status=1) versus (code=killed, signal=KILL) versus 203/EXEC — where do you look for each? B11
  30. A valid signature proves two things and conspicuously fails to prove a third. Name all three, and say what fixes the third. B12

Part B — practical (8 tasks · 70 pts)

Task 1 Bind port 80 without running as root

permissions & capabilities · B4, B118 pts

Create a systemd unit final-web.service that serves ~/final/www on port 80:

  • The process must not run as root — create a system user for it.
  • It must hold exactly one capability, and that capability must also be its ceiling.
  • NoNewPrivileges= must be set.
  • Save the output of ps -o user,args -C python3 --no-headers to ~/final/t1-proc.txt.
Verify:  curl -s localhost:80/index.html   # and the process user is not root

Task 2 Assemble an image by hand

filesystems & overlayfs · B58 pts

Under ~/final/img/ build an overlay with two read-only lower layers and one writable upper, mounted at ~/final/img/merged:

  • The upper layer of the two lowers must win for a file that exists in both — prove it by reading that file through merged.
  • Modify a file that came from a lower layer, then show the lower layer is unchanged.
  • Save findmnt -no FSTYPE,SOURCE,TARGET ~/final/img/merged to ~/final/t2-mount.txt.
Verify:  cat ~/final/t2-mount.txt   # fstype is overlay, target is the merged dir

Task 3 A process that cannot see the machine

namespaces & isolation · B69 pts

Run a shell in new PID, mount and UTS namespaces with a hostname of final-box, and a /proc that reflects the new PID namespace.

  • From inside, save the full process list to ~/final/t3-ps.txt (write it somewhere visible from outside).
  • That file must show your shell as PID 1 and must not list any host process.
  • Also record the inode of the new PID namespace to ~/final/t3-ns.txt.
Verify:  head -3 ~/final/t3-ps.txt   # PID 1 is your shell; nothing from the host

Task 4 Cap a service and prove the cap

cgroups v2 · B7, B119 pts

Create final-burn.service that runs a busy loop, limited to 20% of one CPU and 64 MiB of memory, using unit properties rather than hand-edited cgroup files.

  • Let it run for 30 seconds, then save the throttling evidence — the two relevant lines of its cpu.stat — to ~/final/t4-throttle.txt.
  • Save the effective cpu.max and memory.max values from the unit's cgroup to ~/final/t4-limits.txt.
Verify:  cat ~/final/t4-throttle.txt   # nr_throttled is non-zero

Task 5 A private network with a way out

virtual networking & NAT · B910 pts

Build a network namespace finalns on subnet 10.99.0.0/24:

  • A bridge on the host at 10.99.0.1, a veth pair, and 10.99.0.2 inside the namespace.
  • A default route inside, forwarding enabled, and masquerade so the namespace can reach the host's own primary address.
  • Save ip route as seen from inside the namespace to ~/final/t5-route.txt, and the single NAT rule you added to ~/final/t5-nat.txt.
Verify:  sudo ip netns exec finalns ping -c1 -W2 <the VM's primary IP>

Task 6 Make a name resolve, then prove which source answered

names & resolution · B108 pts

Make the name final.svc resolve to 10.99.0.2 on this machine, without running a DNS server.

  • Prove the resolution works for an ordinary program, not just for a DNS tool — save that command's output to ~/final/t6-resolve.txt.
  • Then demonstrate the disagreement that identifies the source: save the output of the DNS-only query for the same name to ~/final/t6-dns.txt, and write the one-line explanation of why they differ to ~/final/t6-why.txt.
Verify:  getent hosts final.svc   # answers, while the DNS-only query does not

Task 7 A supervised service with operator-editable configuration

service management · B119 pts

Create final-app.service that runs a script printing a message from an environment variable every 5 seconds:

  • The message must come from /etc/default/final-app, not from the unit file.
  • It must restart on failure with a 3-second delay, and be enabled at boot.
  • Change the message in the environment file, make the change take effect, and save the journal lines showing both messages to ~/final/t7-journal.txt.
Verify:  systemctl is-enabled final-app && systemctl is-active final-app

Task 8 Your own CA, and a TLS service that verifies

security & PKI · B129 pts

In ~/final/tls/: create a CA, issue a server certificate for this machine, and serve TLS on port 9443.

  • The certificate must be signed by your CA and must cover both localhost and 127.0.0.1.
  • A client verifying against your CA must succeed without --insecure.
  • Save the certificate's subject, issuer, dates and SAN list to ~/final/t8-cert.txt, and the successful client output to ~/final/t8-client.txt.
Verify:  curl -s --cacert ~/final/tls/ca.crt https://localhost:9443/ | head -1
When the timer rings
  1. Stop. Grade Part A one point per correct answer — partial credit only where the question asks for a list and you got most of it.
  2. Grade Part B with the per-task rubric on the solutions page; each task's points are all-or-most-or-nothing, and the verification command decides.
  3. 66/100 passes. Below that, the useful move is not to retake it — it is to re-read the modules behind the specific things you missed, then retake it a week later.
  4. Restore the VM: multipass restore sandbox.pre-final.
Authored against Ubuntu 24.04 LTS ("noble") on Multipass, verified 2026-07-25. Every task runs on the single throwaway sandbox VM and needs no cluster and no second machine. Part A questions are drawn one or two per module across B0–B13; Part B weights the four layers a container is made of (filesystem, isolation, limits, network) most heavily, because those are the ones the Intermediate track builds directly on.
