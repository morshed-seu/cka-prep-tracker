Beginner final — solutions & grading

Grade yourself honestly: the score is only useful as a comparison against the same rubric later. Where an answer is wrong, the module tag beside it is the instruction — re-read that module's lesson, not this answer. An answer you have memorised from this page is worth nothing on a real machine.

Part A — answers (30 × 1 pt)

  1. multipass launch 24.04 --name sandbox and multipass shell sandbox. Pinning 24.04 rather than lts matters because the lts alias has already moved on to a newer release — a different kernel means different output from the labs you are pasting against. B0.1
  2. First, whether every directory on the path grants execute (traverse) to that user — namei -l. Second, whether something other than the mode is refusing: a mount option (ro, noexec), an AppArmor profile, or the file not being where you think. B1.6 · B4.6
  3. fork() duplicates the calling process; exec() replaces the current process image with a new program. A shell running a background command does both: fork, then exec in the child, and does not wait for it. B2.5
  4. A zombie holds only its exit status, waiting to be collected. Its parent is supposed to wait() for it; if the parent died, PID 1 adopts and reaps it. Killing a zombie does nothing because it is already dead — the fix is to the parent. B2.9
  5. SIGKILL (9). A process killed by it exits with 128 + 9 = 137. B2.8
  6. It traps into the kernel, switching from user mode to kernel mode and back. The transition costs real time (register save, mode switch, possible cache effects), which is why the same "print hello" costs ~30 syscalls in C and ~360 in Python — the doorway is the same, the runtime's weight is not. B3.2
  7. strace; the summarising flag is -c. B3.5
  8. A small integer index into the kernel's per-process table of open things — files, sockets, pipes, devices. By convention 0 is stdin, 1 is stdout, 2 is stderr. B3.7
  9. Owner, then group, then other — and the first matching class decides, so a file owned by you with mode 044 is unreadable by you even though "group" and "other" can read it. B4.5
  10. Execute on a directory means traverse: the right to resolve a path through it. Without it, you cannot reach anything inside no matter how permissive the contents are — and r without x lets you list names but not stat them. B4.6
  11. Capabilities: root's authority split into ~41 individually-grantable permits (e.g. CAP_NET_BIND_SERVICE, CAP_NET_ADMIN, CAP_SYS_ADMIN). The bounding set is the ceiling — the maximum a process can ever hold, including across exec of a setuid binary. B4.10 · B4.12
  12. lowerdir (one or more, read-only, leftmost wins), upperdir (the only one written to), workdir (overlayfs's scratch, must be empty and on the same filesystem as upper), and the merged mountpoint. B5.13
  13. Copy-up: the first write to a file that lives in a lower layer copies the whole file into the upper layer first, then modifies it there. A one-byte change to a 2 GB file therefore costs 2 GB of I/O — and is why databases in containers get a volume. B5.14
  14. findmnt <dir> (or mountpoint <dir>). Something is mounted over the directory, hiding its contents without touching them. B5.11 · B5.12
  15. mnt (its own mount table), pid (its own process numbering), net (its own interfaces, routes and ports), uts (its own hostname), ipc (its own shared memory). Also user, cgroup and time. B6.2
  16. chroot changes what / resolves to but leaves the old root mounted and reachable, so a process with the right privileges can walk back out. pivot_root swaps the mount namespace's root and puts the old one at a path you then unmount — after which there is no path back. B6.10 · B6.11
  17. Mounting a fresh /proc inside. ps reads procfs, and the host's procfs still describes the host — the PID namespace changed numbering, not what /proc shows. B6.5
  18. Namespaces hide; cgroups limit. B7.1
  19. cpu.weight is a proportional share that only matters under contention — a weight of 1 still gets a whole idle core. cpu.max is a hard quota per period and throttles even when the machine is idle. B7.5 · B7.6
  20. The OOM killer, because the cgroup hit memory.max. Proof: memory.events shows oom_kill incrementing, and dmesg/the journal names the killed process. The application's own log is silent because SIGKILL cannot be caught. B7.8
  21. Link (ip link: UP and LOWER_UP) → address (ip addr, including the mask) → route (ip route get) → filter (nft list ruleset / iptables -L -n -v) → listener (ss -ltnp). Climb in order and trust a rung that passed. B8.16
  22. Refused instantly = the packet reached the host and nothing was listening on that port (an RST came back). Hanging = the SYN is being dropped — a filter, a wrong route, or a black hole. Different layers, different next command. B8.9
  23. A veth pair is a virtual patch cable: two interfaces, whatever enters one leaves the other. Deleting either end destroys both — there is no such thing as half a pair. B9.2
  24. Because NAT rewrites addresses and must reverse the rewrite on the reply, which requires remembering the flow — conntrack is that memory. When the table fills, new connections are dropped even though every rule allows them, and the symptom looks like random packet loss. B9.9
  25. PREROUTING. The routing decision happens after that hook, so the destination must be rewritten before the kernel decides where the packet goes. INPUT is too late — and forwarded traffic never reaches INPUT at all. B9.10 · B9.12
  26. /etc/nsswitch.conf — its hosts: line decides which sources are consulted and in what order. ping uses the resolver library (so it sees /etc/hosts); dig talks straight to a DNS server and never does. B10.1
  27. ndots:5 means a name with fewer than five dots is tried against the search list first, so google.com (one dot) generates several failing queries before the literal name is tried. A trailing dot — google.com. — marks it as complete and stops the search-list expansion. B10.3 · B10.4
  28. start acts on the running system now and is forgotten at reboot; enable creates a symlink so the unit is wanted at the next boot and does nothing right now. systemctl enable --now <unit> does both. B11.6
  29. status=1: the program ran and chose to stop — read its logs. signal=KILL: something ended it from outside — look outside the program (OOM, an operator, a timeout). 203/EXEC: systemd could not execute the command at all — check the path, the execute bit and the interpreter; there are no program logs because there was no program. B11.9
  30. It proves origin (the holder of a specific private key made it) and integrity (the data has not changed since). It does not prove who that holder is — an impostor's own signature verifies perfectly against the impostor's own public key. That gap is what a certificate authority closes, by signing a binding between a public key and a name. B12.6 · B12.8

Part B — solutions & rubric (70 pts)

Task 1 Bind port 80 without running as root

permissions & capabilities · B4, B118 pts
sudo useradd --system --no-create-home --shell /usr/sbin/nologin finalweb
mkdir -p ~/final/www && echo ok > ~/final/www/index.html
sudo tee /etc/systemd/system/final-web.service >/dev/null <<'EOF'
[Unit]
Description=final task 1
[Service]
User=finalweb
AmbientCapabilities=CAP_NET_BIND_SERVICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE
NoNewPrivileges=yes
ExecStart=/usr/bin/python3 -m http.server 80 --directory /home/ubuntu/final/www
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now final-web
ps -o user,args -C python3 --no-headers > ~/final/t1-proc.txt
Verify
curl -s localhost:80/index.html          # ok
grep -c '^finalweb' ~/final/t1-proc.txt  # 1 — not root
CriterionPts
Serves on port 80 and curl succeeds3
Process runs as a non-root system user2
Exactly CAP_NET_BIND_SERVICE, in both ambient and bounding set2
NoNewPrivileges=yes present and ~/final/t1-proc.txt written1

Common miss: setting AmbientCapabilities without CapabilityBoundingSet — the permit is granted but the ceiling is still "everything", so the lockdown is half done.

Task 2 Assemble an image by hand

filesystems & overlayfs · B58 pts
cd ~/final && mkdir -p img/{low1,low2,upper,work,merged}
echo 'from low2 (base)'  > img/low2/shared.txt; echo base-only > img/low2/base.txt
echo 'from low1 (upper layer)' > img/low1/shared.txt
sudo mount -t overlay ovl -o lowerdir=img/low1:img/low2,upperdir=img/upper,workdir=img/work img/merged
cat img/merged/shared.txt                       # low1 wins: leftmost lowerdir has priority
echo 'edited' | sudo tee -a img/merged/base.txt >/dev/null
cat img/low2/base.txt                           # unchanged: the edit went to upper/
findmnt -no FSTYPE,SOURCE,TARGET ~/final/img/merged > ~/final/t2-mount.txt
Verify
grep -c overlay ~/final/t2-mount.txt      # 1
sudo ls ~/final/img/upper                 # base.txt — the copied-up file
CriterionPts
Overlay mounted with two lowers, one upper, one workdir3
Demonstrates leftmost-lower priority for the shared file2
Shows the lower layer unchanged after an edit (copy-up)2
~/final/t2-mount.txt written and correct1

Common miss: a non-empty workdir, or workdir on a different filesystem from upperdir — the mount fails with invalid argument and never says why.

Task 3 A process that cannot see the machine

namespaces & isolation · B69 pts
mkdir -p ~/final
sudo unshare --pid --fork --mount --uts --mount-proc /bin/bash -c \
  'hostname final-box; hostname; ps -ef > /home/ubuntu/final/t3-ps.txt; \
   readlink /proc/self/ns/pid > /home/ubuntu/final/t3-ns.txt'
head -3 ~/final/t3-ps.txt; cat ~/final/t3-ns.txt
Verify
awk 'NR==2{print $2}' ~/final/t3-ps.txt   # 1 — the shell is PID 1
wc -l < ~/final/t3-ps.txt                 # a handful of lines, not ~140
CriterionPts
New PID, mount and UTS namespaces (--fork present)3
Hostname is final-box inside and unchanged outside2
t3-ps.txt shows PID 1 and no host processes (i.e. --mount-proc)3
t3-ns.txt records the namespace inode1

Common miss: omitting --fork, or omitting --mount-proc — in the second case everything looks right and ps quietly lists the entire host.

Task 4 Cap a service and prove the cap

cgroups v2 · B7, B119 pts
sudo systemd-run --unit=final-burn --quiet -p CPUQuota=20% -p MemoryMax=64M \
  /bin/bash -c 'while :; do :; done'
sleep 30
CG=/sys/fs/cgroup/system.slice/final-burn.service
grep -E 'nr_throttled|throttled_usec' $CG/cpu.stat > ~/final/t4-throttle.txt
{ echo -n 'cpu.max: '; cat $CG/cpu.max; echo -n 'memory.max: '; cat $CG/memory.max; } > ~/final/t4-limits.txt
sudo systemctl stop final-burn
Verify
cat ~/final/t4-throttle.txt   # nr_throttled non-zero
cat ~/final/t4-limits.txt     # cpu.max: 20000 100000 / memory.max: 67108864
CriterionPts
Limits set as unit properties, not by writing cgroup files by hand3
cpu.max reads 20000 100000 and memory.max is 64 MiB3
t4-throttle.txt shows a non-zero nr_throttled2
t4-limits.txt written1

Common miss: editing cpu.max directly under a systemd-managed unit — systemd reasserts its own value, and the change silently disappears.

Task 5 A private network with a way out

virtual networking & NAT · B910 pts
HOSTIP=$(ip -4 -o addr show scope global | awk '{print $4}' | cut -d/ -f1 | head -1)
sudo ip netns add finalns
sudo ip link add fbr0 type bridge; sudo ip addr add 10.99.0.1/24 dev fbr0; sudo ip link set fbr0 up
sudo ip link add fveth0 type veth peer name eth0 netns finalns
sudo ip link set fveth0 master fbr0 up
sudo ip netns exec finalns ip addr add 10.99.0.2/24 dev eth0
sudo ip netns exec finalns ip link set eth0 up
sudo ip netns exec finalns ip link set lo up
sudo ip netns exec finalns ip route add default via 10.99.0.1
sudo sysctl -qw net.ipv4.ip_forward=1
sudo iptables -t nat -A POSTROUTING -s 10.99.0.0/24 ! -o fbr0 -j MASQUERADE
sudo ip netns exec finalns ip route > ~/final/t5-route.txt
sudo iptables -t nat -S POSTROUTING | grep 10.99.0.0 > ~/final/t5-nat.txt
sudo ip netns exec finalns ping -c1 -W2 "$HOSTIP"
Verify
grep -c default ~/final/t5-route.txt      # 1
sudo ip netns exec finalns ping -c1 -W2 $HOSTIP   # replies
CriterionPts
Namespace, bridge and veth pair created and up3
Correct addressing on both sides of the subnet2
Default route inside plus ip_forward enabled2
Masquerade rule present and the ping to the host address succeeds2
Both evidence files written1

Common miss: forgetting ip link set lo up inside the namespace, or omitting ! -o fbr0 on the masquerade rule so intra-subnet traffic gets NATed too.

Task 6 Make a name resolve, then prove which source answered

names & resolution · B108 pts
echo '10.99.0.2 final.svc' | sudo tee -a /etc/hosts >/dev/null
getent hosts final.svc > ~/final/t6-resolve.txt
dig +short final.svc > ~/final/t6-dns.txt          # empty: DNS never sees /etc/hosts
echo 'getent uses the resolver library, which reads nsswitch.conf and therefore /etc/hosts;
dig talks straight to a DNS server and never consults local files.' > ~/final/t6-why.txt
grep '^hosts:' /etc/nsswitch.conf
Verify
cat ~/final/t6-resolve.txt   # 10.99.0.2  final.svc
wc -c < ~/final/t6-dns.txt   # 0 or a NXDOMAIN-shaped empty answer
CriterionPts
Name resolves for an ordinary program (getent/ping, not dig)3
DNS-only query correctly returns nothing2
Explanation names nsswitch.conf and the resolver library2
All three files written1

Common miss: proving resolution with dig and concluding the name is broken. dig tests the server; getent hosts tests what an application will actually get.

Task 7 A supervised service with operator-editable configuration

service management · B119 pts
printf 'MESSAGE=hello-one\n' | sudo tee /etc/default/final-app >/dev/null
sudo tee /etc/systemd/system/final-app.service >/dev/null <<'EOF'
[Unit]
Description=final task 7
[Service]
EnvironmentFile=/etc/default/final-app
ExecStart=/bin/bash -c 'while :; do echo "$MESSAGE"; sleep 5; done'
Restart=on-failure
RestartSec=3
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now final-app
sleep 6
sudo sed -i 's/hello-one/hello-two/' /etc/default/final-app
sudo systemctl restart final-app          # the environment is read at START
sleep 6
journalctl -u final-app --no-pager -o cat | grep -E 'hello-(one|two)' > ~/final/t7-journal.txt
Verify
systemctl is-enabled final-app && systemctl is-active final-app
grep -c hello-one ~/final/t7-journal.txt && grep -c hello-two ~/final/t7-journal.txt
CriterionPts
Message comes from EnvironmentFile, not from the unit3
Restart=on-failure with RestartSec=3, and unit enabled2
Journal shows both messages, in order3
File written to the right path1

Common miss: editing the environment file and expecting the change to appear without a restart. The environment is copied into the process at start — the same reason a pod's env: from a ConfigMap never updates while a mounted volume does.

Task 8 Your own CA, and a TLS service that verifies

security & PKI · B129 pts
mkdir -p ~/final/tls && cd ~/final/tls
openssl req -x509 -newkey rsa:2048 -sha256 -days 365 -nodes \
  -keyout ca.key -out ca.crt -subj '/CN=Final CA/O=sandbox'
chmod 600 ca.key
openssl genrsa -out server.key 2048; chmod 600 server.key
openssl req -new -key server.key -out server.csr -subj '/CN=localhost'
printf 'basicConstraints=CA:FALSE\nkeyUsage=critical,digitalSignature,keyEncipherment\n\
extendedKeyUsage=serverAuth\nsubjectAltName=DNS:localhost,IP:127.0.0.1\n' > san.ext
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -days 365 -sha256 -extfile san.ext -out server.crt
openssl s_server -accept 9443 -cert server.crt -key server.key -www &>/dev/null &
sleep 1
openssl x509 -in server.crt -noout -subject -issuer -dates -ext subjectAltName > ~/final/t8-cert.txt
curl -s --cacert ca.crt https://localhost:9443/ | head -1 > ~/final/t8-client.txt
Verify
grep -c 'DNS:localhost' ~/final/t8-cert.txt   # 1
test -s ~/final/t8-client.txt && echo verified-without-insecure
CriterionPts
CA created; server key and CSR generated separately from it2
Certificate signed by the CA (issuer is the CA, not itself)2
SAN list covers both DNS:localhost and IP:127.0.0.13
Client verifies without --insecure; both files written2

Common miss: putting the hostname only in the CN. Modern clients ignore CN for name matching entirely — no SAN, no connection, with an error that points at the name rather than at the missing extension.

A pass here means the beginner track has done its job: you can explain what a container is in kernel terms and build one, put a process in a namespace and a cgroup, build a bridged network with NAT and prove it, issue and verify a certificate, and place a symptom on the right rung of the ladder. That is the entry condition for the Advanced track — and for the Intermediate track when it lands, which restarts from exactly the capstone you built in B14.4.

Below 66, the useful move is not an immediate retake. Re-read the modules behind the specific misses, redo those modules' projects, and come back to this page in a week — a second score against the same rubric is the only comparison that means anything.

Authored against Ubuntu 24.04 LTS ("noble") on Multipass, verified 2026-07-25. Solutions are written for the single throwaway sandbox VM; paths assume the default ubuntu user. Where a task has more than one correct answer — systemd-run versus a unit file with a drop-in, ip netns versus unshare --net — the rubric grades the property being tested, not the route taken.
