## Commands

**Authoring a module page? Read [`docs/AUTHORING.md`](docs/AUTHORING.md) — the one-page session runbook.** It supersedes re-reading the long tables below.

```bash
python3 -m http.server 8000         # serve locally → http://localhost:8000

# checkers — run all four before considering a phase finished
tools/check-links.sh                # all three tracks: tracker checkpoint <-> lesson anchor, both ways
                                    #   index.html    data-id="wN-M" <-> materials/wN.html  id="cp-N-M"
                                    #   beginner.html data-id="bN-M" <-> materials/bN.html  id="cp-bN-M"
                                    #   intermediate.html data-id="iN-M" <-> materials/iN.html id="cp-iN-M"
tools/check-html.py                 # tag-balance; defaults to every tracker + materials/cheatsheets/mock
tools/check-page.py [--anatomy]     # raw <word> in <pre> (check-html.py CANNOT see this), &-as-entity,
                                    #   broken links, dangling deep anchors, lesson.js wiring,
                                    #   un-captured output. Tuned to zero false positives: if it
                                    #   fires it is real. --anatomy adds advisory block-structure checks.
node --check assets/lesson.js       # syntax-check the shared JS

# authoring helpers
tools/scaffold-module.py i4         # generate materials/i4.html from the tracker section:
                                    #   every stub, id and boilerplate, with each checkpoint's text
                                    #   and "Under the hood" note inlined as comments. Write prose only.
tools/publish-module.sh i4          # PUBLISHED bump + sibling Site lists + previous pager next + verify.
                                    #   Pre-flights the page and refuses one containing TODO.
tools/vm.sh run|cap|put|get|clean   # run lab snippets on the `sandbox` VM without the hang/transfer traps
```

There is no build step, package manager, linter, or test framework beyond the `tools/` scripts above — run the four checkers (plus a visual spot-check in the browser: theme toggle, done-sync with the tracker, anchors landing right) before considering a phase finished.

## Architecture

- **Two trackers, same shape**: `index.html` (CKA weeks) and `beginner.html` (B-modules) are each the source of truth for their own checkpoints. Each carries its own inline `PUBLISHED` array (module/week numbers that have a lesson page) and `EXTRAS` array (`{t:'title', href:'...'}`), which drive the `lesson` links and sidebar entries. Publishing a lesson page = adding its number to that tracker's `PUBLISHED`.
- **Anchor scheme**, one rule for both tracks — **anchor id = `cp-` + data-id with a leading `w` stripped**: `index.html`'s `<li data-id="wN-M">` ↔ `materials/wN.html`'s `<article class="lesson" id="cp-N-M">`, and `beginner.html`'s `<li data-id="bN-M">` ↔ `materials/bN.html`'s `id="cp-bN-M"`. Bidirectional, enforced by `tools/check-links.sh`.
- **Shared client state**, all via `localStorage`, same-origin so it works free on GitHub Pages: `cka-prep-v1` (checkpoint done/undone — **one key for both tracks**, ids namespaced by the `b` prefix, so cross-track sync is free and each tracker's reset button filters to its own prefix), `cka-theme` (light/dark, `data-theme` attribute), `cka-collapsed-v1` / `cka-grp-collapsed-v1` (section + group collapse). `assets/lesson.js` wires every lesson page into these; the two trackers have their own copies of the tracker/theme logic inline.
- `assets/site.css` is the single stylesheet for every page (both trackers, lessons, cheat sheets, mock exam) — includes `@media print` rules cheat sheets depend on to fit one page. Beginner-track blocks (`.tracks .objectives .prereq .outcome .lesson.project .lesson.drill .k8s-link .langpair .modlist .godeep`) live at the end; the box headings are CSS `::before` content, so authors write `<div class="k8s-link">` and get the mandatory heading for free.
- The **three-pill track switcher** (`.tracks`) sits in every sidebar directly after `.brand-row`, with `class="on"` on the current track and Intermediate as an inert `<span>`. Root pages link `beginner.html`/`index.html`; pages in `materials/`, `cheatsheets/`, `mock/` prefix `../`. Per-page "Site" lists are *not* merged across tracks — the switcher is the only crossing point.
- Lesson pages are otherwise independent static files with no shared templating — conventions below are enforced by convention + the check scripts, not by a build step.

Also confirmed: the advanced track has **no** `securityContext` / Pod Security Standards anchor anywhere — don't invent one, say so and link what exists (I11.5 does). **Confirmed live on 2.3.3 in I-S5:** `containerd config default` emits **`version = 4`** (2.0 moved 2→3, 2.3 moved 3→4) and still carries a legacy `plugins.'io.containerd.grpc.v1.cri'` section alongside the split `io.containerd.cri.v1.runtime` / `io.containerd.cri.v1.images` plugins — I7/I8 must not repeat the bare "version 3" claim. `runc --version` reports `spec: 1.3.0`, matching `ociVersion` in a `runc spec` bundle. **Confirmed live on kernel 6.8.0 in I-S6** (all binding on I11 and I3 in particular): Ubuntu 24.04's `kernel.apparmor_restrict_unprivileged_userns=1` **does not block user-namespace creation** — the stock `unprivileged_userns` profile carries `allow userns` *and* `audit deny capability`, so `unshare --user` succeeds with `CapEff: 0`, and every downstream `EPERM` traces to that empty set with no error message naming AppArmor; the correct workaround is a named profile granting `userns,` for one binary by path, not the sysctl. The containerd/Docker default seccomp profile has **moved to `github.com/moby/profiles`** (all `moby/moby` links 404) and lists **442** syscall names, not "~300", with a `clone` rule masking `0x7E020000` — i.e. *all* `CLONE_NEW*` bits. **Unprivileged overlayfs inside a userns+mountns works**, so `fuse-overlayfs` is not required (that advice predates kernel 5.11). Cgroup delegation gives a user `cpu memory pids` only (no `cpuset`, no `io`), and a process **cannot migrate itself** into a cgroup it created under `user@UID.service` — migration is checked on the common ancestor — so use `systemd-run --user --scope`. "eth0 deleted from inside" and "namespace deleted first" both leak), while the **IPAM reservation is released in all three** because IPAM is keyed by container ID and the nat rule by the address. `portmap`'s DNAT rules also survive `DEL` unless the **capability args are replayed** — `cnitool` does not read them back from its own cache (4 rules remaining, exit 0; 0 when `CAP_ARGS` is re-supplied), whereas containerd does replay them, so a real teardown is clean. **`host-local`'s reservation files are CRLF** (`backend/disk/backend.go`: `LineBreak = "\r\n"`, confirmed with `od -c`), contain container ID **and** ifname, `last_reserved_ip.0` survives `DEL`, and allocation **walks forward and never backfills**. **Biggest correction: `GC` is a well-formed no-op on plugins v1.9.1** — **not one of the ten reference plugins registers a GC handler** (`host-local`'s `main.go` has only `cmdAdd`/`cmdDel`/`cmdCheck`), so an explicit `cni.dev/valid-attachments` list, even an empty one, reclaims nothing; `skel` dispatches and version-gates the verb (GC at `cniVersion` 1.0.0 → code 1 `config version does not allow GC`) and then calls nil. libcni's `GCNetworkList` is **two phases** — synthesised `DEL`s for **cached** attachments, then the verb — and the cache lives in `/var/run` (tmpfs) while reservations live in `/var/lib`, so **a reboot destroys phase one's input and preserves exactly what GC exists to reclaim**. libcni also injects the list under **two** keys (`cni.dev/valid-attachments` *and* `cni.dev/attachments`, `// #1101: spec used incorrect variable name`). **`cnitool gc` passes `nil`** ("Currently just invoke GC without args, hence all network interface should be GC'ed!"), i.e. it means "release every cached attachment, live ones included" — measured tearing down all three. `STATUS` is answered by every plugin and **always says ready**: `host-local` never returns code **50** even with the pool full. `cnitool` is **not packaged for noble** (`go install …/cnitool@v1.3.0`) and derives `CNI_CONTAINERID` **deterministically from the netns path**, which makes idempotency testing easy and stale-reservation collisions confusing. Smaller facts worth reusing: `macvlan` mints its **own** MAC where `ipvlan` shares the parent's **byte for byte**; a fresh netns answers `ping 127.0.0.1` with **"Network is unreachable"** (hence mandatory `loopback`, called with `CNI_IFNAME=lo`, and containerd's `useInternalLoopback` doing it in-process); `bridge` sets `hairpin_mode=1`, `accept_ra=0` on the host veth and `arp_notify=1` inside, none of which B9's `net-up.sh` did; `static` IPAM will hand the **same address to two namespaces** without complaint; the `dns` key vanishes from results at 1.x when empty and 0.2.0 has no `interfaces` array at all; and **alpine 3.21's busybox has `nc` and `wget` but no `httpd`**. Ships `labs/intermediate/cni-minibridge` (430 lines of bash+jq implementing all six operations, driven by `cnitool` and then by **containerd for a real `crictl runp`** — containerd took its address, `portmap` chained onto its result, `curl` got HTTP 200 through the mapping and teardown left 0/0/0; it deliberately fixes the three gaps above: store-based `DEL`, a real `GC`, and `STATUS` code 50), plus `i9-dump` (a chained plugin that reveals `prevResult`) and `i9-reset.sh`. Three ops traps cost a round each and are now in `docs/AUTHORING.md`: **`sudo` with a shell redirect or glob is evaluated by the unprivileged shell first** (`sudo tr < file`, `sudo rm /etc/cni/net.d/00-*` on a 0700 dir — wrap in `sudo sh -c`); **two concurrent `tools/vm.sh` calls race on the same `~/.vmrun/out`** and interleave output; and **Go's `context.TODO()` in a quoted source line trips both `check-page.py` and `publish-module.sh`** — mark it as an elision rather than loosening the gate. **Confirmed live in I-S15** (binding on I11–I13 and on any storage claim): the **CSI spec is v1.13.0** (2026-07-27), not v1.11.0 — and the reference **`hostpathplugin` is v1.18.0**, a number that predicts nothing about the spec version. That driver **advertises Controller capability 11 and Node capability 4, neither of which exists in v1.13.0's enums** (they have gaps: 10 then 12; 3 then 5) — both were `VOLUME_CONDITION`, since replaced by the `GET_VOLUME_HEALTH` family at different numbers — so a client calling `Type.Name()` on the raw value dies with `ValueError` **against a healthy driver**; always fall back to `<unknown:N>`. `Probe` returns an **unset** readiness, and the spec says unset means ready, so reading `.ready.value` without `HasField` declares a healthy driver dead. The spec is 2373 lines and **36 rpcs: Identity 3, Controller 17, Node 10, plus SnapshotMetadata 2 and GroupController 4** — the familiar "three services" framing no longer covers it. **`crictl imagefsinfo` counts only what the CRI created**: 300 MB written through `ctr -n k8s.io` moved it by **zero** bytes while the same write through `crictl` moved it by 314 MB, and it reported 9,986,048 bytes against **2.3G** on disk (3 k8s.io snapshots vs 167 in `default`/`buildkit`) — a node's disk can be full of storage the kubelet's eviction input cannot see. Its JSON nests under **`.status`**, and container stats are **windowed**, not on demand. Snapshot removal is **asynchronous** (upperdir present at +600 ms after `container rm`, gone by +800 ms). Copy-up measured: appending **one byte** to alpine's `libcrypto.so.3` took the writable layer from 12 B to **4,498,781 B**. On propagation, two corrections to the usual telling: **a bare runc bundle's default is `master:1` — slave, not private** — so host→container propagation works by default and a bundle test proves nothing about a pod (Kubernetes' default `mountPropagation: None` asks explicitly for `rprivate`); and **`rshared` on the mount alone is not enough** — it yields `shared:N master:1`, a slave sharing only with itself, and only `linux.rootfsPropagation: rshared` gives `shared:1`, the host's own peer group, after which the escaped mount appears **twice** in the host table. A stock `runc spec` grants three capabilities and **`CAP_DAC_OVERRIDE` is not among them**, so container root **cannot** create a file in a uid-1000 directory (appending to a root-owned file still works) — a storage bug that is really B4.10. A `tmpfs` with no `size=` advertises **half of RAM** (1.9G) against a 128 MiB cgroup limit, and filling it OOM-kills with `oom_memcg` named and **no mention of storage**; the identical write reports **exit 0 when piped into `tail`** and 137 when not, so an OOM-killed container can show no `OOMKilled` reason and no restart. On CSI ordering: publishing before staging is refused (`FAILED_PRECONDITION`, zero mounts), unstaging is **refcounted** (`INTERNAL` while any publication remains, with the paths in the message body), but **`DeleteVolume` does not check for live mounts** — it destroyed a volume with two pod mounts outstanding, which then read `//deleted` and could no longer be unpublished (`NOT_FOUND`), which is exactly what PV finalizers exist to prevent. `fsGroup` measured: `chown -R` over **50,000 files = 0.48 s cold / 0.18 s warm; 500,000 = 5.74 s cold**, against **0.00 s** for `OnRootMismatch`'s single `stat` — "minutes" requires network-backed storage, so never quote it for local disk. **`node-driver-registrar` makes no Kubernetes API calls and needs no RBAC** (its own README; the sidecar summary page implies it watches Node objects — it does not), and **there is no sidecar for the Node service**: the kubelet makes `NodeStageVolume`/`NodePublishVolume` itself. Two environment facts: **`runc` refuses a user-namespace bundle on this host** with `remount-private dst=<rootfs> MS_PRIVATE: permission denied` regardless of whether the rootfs is a mount point, is made private first, or runc runs inside a private mount namespace — `CapEff` is full, so this is *not* I-S6's AppArmor cap-stripping; use `unshare --map-users` (subuid-backed) to demonstrate id mapping instead, noting that `--map-root-user` is itself refused here with `write failed /proc/self/uid_map`. Ships `labs/intermediate/csi-probe.py` (drives a real driver through Identity/Controller/Node from stubs generated off the spec's own `csi.proto`) and `volman.py` (named volumes on loop-mounted ext4, attached by rewriting `config.json`'s mounts array, verbs named after the CSI calls, `rm` refusing while referenced). **Confirmed live in I-S16** (binding on I12, I13 and on any hardening claim): a bare `runc spec` bundle emits **three** capability sets, not five — no `inheritable`, no `ambient` — holding three capabilities (`0x20000420`), and sets **`noNewPrivileges: true`** and **`root.readonly: true`** already, so the tracker's I11.2/I11.5 wording ("set it to true") is backwards and the "roughly fourteen capabilities by default including CAP_CHOWN/CAP_SETUID/CAP_NET_RAW/CAP_MKNOD" figure is **Docker's** set, not runc's. Of the five arrays only **`bounding`** is ever load-bearing: for a **root** container the kernel recomputes effective′ = permitted′ at `execve`, so `CAP_CHOWN` placed only in bounding+permitted came out with `CapEff 0x…421` and the `chown` succeeded — the `effective` array is a **no-op**; for a **non-root** container `permitted` *and* `effective` are both wiped to zero (uid 1000 with `CAP_CHOWN` in all three arrays got `CapPrm`/`CapEff` = 0), which is exactly a pod combining `runAsNonRoot` with `capabilities.add`, and the only fix is `ambient` — which the kernel refuses unless the capability is also in `inheritable` (`can't raise ambient capability CAP_CHOWN: operation not permitted`). A misspelled capability is a **warning** and the container starts with the default set, and the spec asks for exactly that ("Runtimes SHOULD NOT fail"), so a typo in a hardening config fails open. On seccomp: a bare bundle has **no `linux.seccomp` at all** (the "runtime default profile" is containerd's, not runc's); **`architectures` ADDS architectures and does not select** — a profile listing only ARM still blocked `mkdir` on x86-64; one `args` block applies to **every** name in its `syscalls[]` entry while argument positions differ per syscall (`chmod(path,mode)` index 1 under musl, `fchmodat(dirfd,path,mode,flags)` index 2 under glibc), so grouping them produced a rule that silently never fired; `SCMP_ACT_KILL_PROCESS` kills **the process that made the call**, so a forked `mkdir` died while the shell printed its next line and the container exited 0. Hand-writing an allow-list took **four rounds — 29 → 30 → 71 → 74 names — to run `echo`**, because the filter also covers `runc init`: at 29 it failed with `fcntl(F_DUPFD_CLOEXEC): operation not permitted`, at 30 with libpathrs' Rust panic *"at least one candidate /proc/thread-self path should work"* (missing `openat2`/`statfs`). Switching `defaultAction` to `SCMP_ACT_KILL_PROCESS` makes `dmesg` name the culprit — `type=1326`, `comm="runc:[2:INIT]"`, `syscall=72` — and that pairing is the whole diagnostic technique. On MAC: an AppArmor **`deny` rule blocks the access and logs NOTHING**; only `audit deny` emits the `DENIED` record, so the tracker's I11.4 text ("confirm the denial appears in the audit log") is wrong for the rule as usually written; an unloaded profile fails the container at init with `write /1/task/1/attr/apparmor/exec: no such file or directory` while only the kernel record says `info="label not found"`; and `selinuxLabel` on a non-SELinux host is **refused outright**. On read-only rootfs: `apk add` fails at **rc=99** before doing anything, and with `tmpfs` over `/tmp`, `/var/cache/apk` and `/lib/apk/db` it reaches **rc=17** — seventeen failed renames into the rootfs itself — while printing *"8 MiB in 17 packages"* with `jq` not installed, so the standard `tmpfs` fix **cannot rescue a package manager**; `root.readonly` does **not** touch bind mounts (a `rw` bind wrote through to the host in the same container that got EROFS for `/`), and `maskedPaths` is `/dev/null` bind-mounted over the file (`/proc/kcore` is char device `1,3`). On rootless: `runc spec --rootless` maps exactly **one** id, drops the **network** namespace, emits no `cgroupsPath`/`resources` and rbinds the host `/sys` read-only; widening it to `/etc/subuid` fails with **`fchown fd 7: operation not permitted`** and chowning the rootfs first does not help because `chown 100000:100000` is itself EPERM for an ordinary user — so subuid-backed rootless **requires** a helper (rootlesskit) to build the userns with `newuidmap` first, which is why the spec says *"The runtime SHOULD NOT modify the ownership of referenced filesystems to realize the mapping"*. Stock Ubuntu 24.04 blocks it at `failed to unshare remaining namespaces: Operation not permitted` — I1.4's wall, because `unprivileged_userns` pairs `allow userns` with `audit deny capability` — fixed with a named `flags=(unconfined)` profile granting `userns` per binary path. **`ps` inside a user namespace reports uid 0**; the host-side check must run outside, where `unshare --map-users=100000,0,65536` shows uid **100000**. Rootless containerd's unit MainPID is **rootlesskit**, not containerd (a grandchild), and containerd logs `address=/run/containerd/containerd.sock gid=0 uid=0` — the *same path string* as the root daemon, a different file inside rootlesskit's mount namespace, with a separate image store; its `uid_map` has **two** lines (`0 1000 1` + `1 100000 65536`); privileged ports fail in the **host-side** port proxy with an error naming all three fixes; the container network is slirp4netns's private **10.4.0.0/24**, invisible to host iptables; and **cgroup delegation has grown** — `user@1000.service` now delegates `cpuset cpu io memory hugetlb pids rdma misc` and `--memory`/`--cpuset-cpus`/`--pids-limit` all produced real limits, so I-S6's "only `cpu memory pids`" note is out of date. The headline A/B: `ctr` (root) bind-mounting `/` printed `root:*:20639:0:99999:7:::`; the same request under rootless `nerdctl` got **Permission denied**. On supply chain, **cosign v3.1.2** refuses `--tlog-upload=false` ("not supported with --signing-config") and its own error contains the recipe — a signing config with `rekorTlogUrls` deleted; it stores signatures as **OCI referrers**, not the v2 `.sig` tag, and since `registry:2` does not implement `/v2/<name>/referrers/<digest>` (404) it used the spec's fallback tag `sha256-<hex>` (**no `.sig` suffix**) holding an **index** — so fetching it is I5.4 again, 404 for `Accept: image.manifest.v1+json` and 200 for `image.index.v1+json`. **`cosign triangulate` is deprecated and now wrong**, printing a `.sig` path that 404s for a signature that is present; `cosign tree` reports the truth *unless the tag has moved*, in which case it resolves the tag too and says "No Supply Chain Security Related Artifacts found" — confirming the wrong conclusion. The signature manifest is an ordinary OCI manifest (`artifactType application/vnd.dev.sigstore.bundle.v0.3+json`, `subject` = image digest, `config` = `application/vnd.oci.empty.v1+json`, one layer) carrying an **RFC3161 timestamp even with the tlog off**; attestations use the identical shape and join the same index, and asking `verify-attestation` for an absent predicate type helpfully lists the present ones — including the signature itself as `https://sigstore.dev/cosign/sign/v1`. **SBOM counts are not comparable across formats**: one alpine image is 15 artifacts (syft-json), 16 packages (SPDX-2.3) and 98 components (CycloneDX 1.7 = 82 file + 15 library + 1 operating-system). Package counts — distroless/static 4, distroless/base 6, alpine 15, ubuntu:24.04 92, python:3.13 479 — predict trivy findings exactly: 0, 13, 0, 42, **2594**. **Two scanners disagree on severity, not just totals**: the same three CVEs in the same `libc6@2.36-9+deb12u14` are Critical/High/High to grype (NVD CVSS) and **MEDIUM/MEDIUM/MEDIUM** to trivy (Debian's assessment), with identical 13-finding totals — so a "block on any critical" gate passes under one tool and fails under the other on identical bytes (ubuntu 42 vs 109; python:3.13 2594 vs 1946). Reachability, measured: python:3.13's first critical is `CVE-2026-49261` in **`libmariadb-dev`**, whose syft `locations` are *all* dpkg bookkeeping and whose code nothing links (`ldd` on the interpreter shows four libraries, none of them MariaDB's) — a true finding on no executed path, fixed by deleting a `-dev` package. The **distribution spec contains no tag-mutability language at all** (grep for immutable/overwrite against tags returns nothing), so tag immutability is a registry feature and not a property of the format; re-pushing by hand is two blob PUTs and a manifest PUT answering `201 Created` with a new `Docker-Content-Digest`, after which verifying **by tag** gives `Error: no signatures found` while the same signature verifies by digest — the drill's second fault, whose message points at the key and not at the tag. Also confirmed: the referrers fallback is a **MUST** ("If the referrers API returns a 404, the client MUST fallback"), the runtime spec's abstract mentions **neither security nor isolation**, and the CVSS v3.1 spec does **not** contain the widely-quoted "CVSS measures severity, not risk" sentence (it says business factors "are outside the scope of CVSS"). ## Plain-English lesson voice (R0–R8)

Supersedes the old EP0–EP8 toggle-based enrichment pass (history + pivot rationale in `docs/PLAN.md`'s EP0–EP8 addendum). Feedback: bolting optional `.foundation` panels onto otherwise jargon-dense prose wasn't enough — readers experienced fully-detailed lessons as if they were terse hints, because the surrounding sentences assumed background they didn't have. Goal now: rewrite the core prose itself so plain language leads and full depth follows, in one voice, for every reader — nothing hidden, nothing to toggle.

Apply this recipe to every `<article class="lesson">` when rewriting a week (R1–R8):

- **Why it matters** — open with one plain-English sentence naming the thing and why a newcomer would care, before the existing exam-relevance framing. Every lesson gets this, not just primitive-heavy ones.
- **The concept** — plain language first, precision second: define each dense term inline in plain words on first use in the lesson (CRI, gRPC, veth, DNAT, quorum, SAN, admission, reconcile loop…) rather than leaving clarity to an `<abbr>` tooltip alone. Reach for **one** analogy from the registry below where it actually clarifies — don't stack metaphors for the same idea. Then deliver the same internals detail the lesson always had, unabridged: depth is never cut for accessibility, only unpacked more gradually. Expand any paragraph or bullet list that currently compresses several ideas into one dense clause into the connected reasoning a beginner needs to follow. - Keep `<abbr title="short plain definition">term</abbr>` on first jargon use per lesson — cheap, still a useful hover reference even though it's no longer the primary clarity mechanism.
- `materials/foundations.html` remains the standalone primer for cross-cutting fundamentals (processes/containers, APIs/declarative, YAML, TCP/IP+DNS, PKI/TLS, consensus/quorum, Linux networking primitives, systemd/static pods) — link into its sections for an optional deeper dive rather than re-deriving a primitive from scratch inside a week's lesson.
